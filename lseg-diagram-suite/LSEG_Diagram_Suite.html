One shared mental model for the forecast.

These diagrams lock the core forecasting principles for LSEG's Strategic Account Management forecast — deal-based, monthly, built in Pigment and sourced Salesforce → Snowflake → Pigment — so business and technical stakeholders share one picture before any screens are designed.

These are not wireframes and are not meant to look like the application. All content is Viridian-proposed, not yet LSEG-ratified. Plain business language, British English throughout. Open questions are flagged, not silently resolved.

01

Forecast Layers

Build-up stack

The full build-up: a deal-based foundation, overlays stacked most-known to most-assumed, summing to a single submitted number. Certainty and time are the same axis.

%%{init:{'theme':'base','themeVariables':{'lineColor':'#5E82BE','fontFamily':'ui-sans-serif, system-ui, sans-serif'}}}%%
flowchart BT
  FRAME["v0.1 · Conceptual · For validation · Viridian-proposed, not LSEG-ratified"]:::frame
  DEAL["DEAL-BASED LAYER — values set and adjusted here, always traceable to the deal.<br/>Binary calls: Commit (default In) / Best Case (default Out) / Material Pipeline (above threshold) — full value, binary in/out.<br/>Deal-level adjustment: value override / hedge on a committed deal (stays attached to the deal)."]:::deal
  EARLY["Early Stage Pipeline Overlay — the deal-based to overlay transition point.<br/>Uses the known below-threshold tail. Levers: Timing (shift ± months) / Value (unweighted total) / Win rate %.<br/>Output = weighted and phased, traceable to the tail deals."]:::ov1
  NEW["New Deals Not in Pipeline — models deals not yet created.<br/>Drivers (each vs an actuals reference point): Added to Pipeline / Avg Deal Cycle Time / Likely Win Rate / Avg Deal Value."]:::ov2
  REN["Renewal-Based Overlay (OPEN — data-dependent, confirm with business; position overrideable).<br/>Renewals due for review. Drivers: Available to Review / Renewal %.<br/>Output splits: renews = Gross Sales, lapses = Cancellations."]:::ren
  TGT["Target / Aspirational — simple manual input by forecast type (Gross Sales, Cancellations)."]:::tgt
  OUT["= SINGLE SUBMITTED FORECAST — one number, the sum of every layer below."]:::out
  LENS["Cross-cutting lenses (read ACROSS every layer, not layers themselves):<br/>Swing / range (worst / most-likely / best) and Budget vs forecast (path-to-plan reference)."]:::note
  AXIS["Certainty / time axis (same axis): near months (CM, CM+1) lean on lower layers (higher certainty);<br/>far months (CM+2 onward) lean on upper layers (more assumption)."]:::axis

02

Deal Decision Tree

Per-deal flow

One deal's journey: a materiality gate, the binary in/out call, a three-lever risk triage (each lever with one job, no overlap), rolling up to most-likely, best and worst.

%%{init:{'theme':'base','themeVariables':{'lineColor':'#5E82BE','fontFamily':'ui-sans-serif, system-ui, sans-serif'}}}%%
flowchart TD
  FRAME["v0.1 · Conceptual · For validation · Viridian-proposed, not LSEG-ratified"]:::frame
  START(["Deal in Salesforce<br/>category / value / close month"]):::start
  MAT{"Material?<br/>above threshold (channel / region / business line)"}:::dec
  TAIL["Non-material tail<br/>Early Stage Pipeline Overlay (formulaic, greyed, not called deal-by-deal)"]:::tail
  CALL{"Set the in/out call<br/>default from category, forecaster can override"}:::dec
  COMMIT["Commit = IN the most-likely (full value)"]:::inn
  BEST["Best Case = OUT = upside range"]:::outn
  MATU["Material, can't Commit = OUT = upside range<br/>option: pool as a weighted set (OPEN — needs James/Ken sign-off)"]:::open
  TRIAGE{"Reflect reality:<br/>what kind of risk?"}:::dec
  VAL["How big? scope / size risk<br/>ADJUST VALUE (500k to 250k)<br/>delta vs Salesforce = upside. Never a probability haircut."]:::lever
  TIME["When? timing risk<br/>CHANGE MONTH (Jul to Aug)<br/>delta vs SF close = timing shift"]:::lever
  SWING["Whether? all-or-nothing risk<br/>KEEP FULL VALUE + FLAG SWING<br/>in = downside floor / out = already upside. The only job of the swing flag."]:::flag
  ROLL["Rolls up to three numbers"]:::hub
  ML["MOST-LIKELY (submitted)<br/>= sum of deals IN, at adjusted value and month"]:::rml
  BESTN["BEST / upside<br/>= most-likely + Salesforce delta (raw CRM ceiling)"]:::rbest
  WORST["WORST / downside<br/>= most-likely minus flagged IN-deals that could fail"]:::rworst

  TRIAGE --> SWING

  SWING --> ROLL
  ROLL --> ML
  ROLL --> BESTN
  ROLL --> WORST

03

Layer Migration

Vertical bridge

Each overlay is a forward promise that resolves downward into deal-based reality over cycles. The gap at each hand-off is a calibration rate you carry forward.

%%{init:{'theme':'base','themeVariables':{'lineColor':'#5E82BE','fontFamily':'ui-sans-serif, system-ui, sans-serif'}}}%%

  FRAME["v0.1 · Conceptual · For validation · Viridian-proposed, not LSEG-ratified"]:::frame
  subgraph M["This cycle (M): the forecast — promises"]
    direction TB
    NEWM["New Deals overlay<br/>modelled, not yet in pipeline"]:::ov
    EARLYM["Early Stage overlay<br/>below-threshold tail"]:::ov
    RENM["Renewal overlay (OPEN)<br/>Available to Review / Renewal %"]:::ovopen
    BESTM["Best Case (out of forecast)"]:::ov
  end
  subgraph MN["Next cycle (M+1): what materialised — reality"]
    direction TB
    EARLYR["Early-Stage pipeline<br/>now real deals"]:::real
    DEALR["Material deal-based<br/>real deal calls"]:::real
    GCR["Gross Sales / Cancellations"]:::real
    COMMITR["Commit"]:::real
  end
  NEWM -->|"created — promised 1.0m to landed 0.7m (70% creation rate)"| EARLYR
  EARLYM -->|"crosses threshold — 75% materialised"| DEALR
  RENM -->|"renews / lapses"| GCR
  BESTM -->|"upside converts"| COMMITR
  TWO["Two events per layer, measure BOTH:<br/>Materialised (did the deals show up below?) vs Converted (did they then win?).<br/>Strong creation with weak conversion is a different problem from the reverse."]:::note
  PAY["Payoff: over cycles each assumption becomes an empirical calibration rate carried forward.<br/>BUILD REQUIREMENT (design in from the start — cannot be reconstructed later):<br/>stamp each deal with the overlay + period that anticipated it."]:::req

  MN -.- PAY
  M -.- FRAME

Planning Principles

Philosophy

The north star and the three pillars beneath it — the number we submit, how we handle uncertainty, and how we improve every cycle.

  FRAME["v0.1 · Conceptual · For validation · Viridian-proposed, not LSEG-ratified"]:::frame
  NS["NORTH STAR — Plan as close to reality as we can:<br/>one traceable number that gets sharper every cycle"]:::ns
  P1["1. The number we submit"]:::h1
  P2["2. How we handle uncertainty"]:::h2
  P3["3. How we improve every cycle"]:::h3
  NS --> P1
  NS --> P2
  NS --> P3
  NS -.- FRAME
  P1 --> A1["Reflect reality — the month and value we genuinely expect, not raw CRM"]:::c1
  P1 --> A2["Binary and full value — no probability weighting in the foundation"]:::c1
  P1 --> A3["One number, one view — never parallel sales vs account-management forecasts"]:::c1
  P2 --> B1["Uncertainty has a home — reducible moves the estimate, irreducible becomes the range"]:::c2
  P2 --> B2["The range is derived, not entered — Salesforce delta (upside) + risk flag (downside)"]:::c2
  P2 --> B3["Deal-based first — overlays only fill genuine visibility gaps"]:::c2
  P3 --> C1["Everything traceable — drill from any number to the deals behind it"]:::c3
  P3 --> C2["Every layer a testable hypothesis — measure and refine the assumptions"]:::c3
  P3 --> C3["Guided, not automated — the tool suggests, the forecaster decides; hygiene is structural"]:::c3

Swimlaned

The monthly cycle across role lanes — from the Account Manager keeping Salesforce honest, through build, submit, review and sign-off, to the frozen snapshot and write-back.

06

Solution / Data-flow Architecture

Conceptual

Salesforce → Snowflake → Pigment → downstream, at the conceptual level. The load-bearing principle: business logic lives in Pigment, not baked into the Snowflake layer.

%%{init:{'theme':'base','themeVariables':{'lineColor':'#5E82BE','fontFamily':'ui-sans-serif, system-ui, sans-serif'}}}%%
flowchart LR
  FRAME["v0.1 · Conceptual · For validation · Viridian-proposed, not LSEG-ratified"]:::frame
  subgraph SFG["Salesforce — system of record"]
    direction TB
    SF["Opportunities / deals: category, value, close month.<br/>Two owner keys (account owner + opportunity owner).<br/>Annual (January) FX rate."]:::sys
  end
  subgraph SNG["Snowflake — transform / curated layer"]
    direction TB
    MASTER["'Master pipeline' output table — already feeds approx 90% of LSEG reporting.<br/>Carries pipeline + plan (budget) + actuals,<br/>distinguished by a source / identifier field. Refresh approx hourly."]:::sys
    DIMS["Dimension / mapping tables (managed separately):<br/>two people-hierarchies keyed to Workday staging by employee number<br/>(levels 6 / 5 / 4 = account director / market head / regional head),<br/>product hierarchy (finance master data), region hierarchy,<br/>reporting-market carving (Partners, LCC)."]:::dims
  end
  WD["Workday — staging table<br/>(employee-number key)"]:::src
  subgraph PGG["Pigment — the forecasting layer"]
    direction TB
    PIG["Direct read · delta loads · minimal access.<br/>BUSINESS LOGIC LIVES HERE (visible, adjustable):<br/>routing / eligibility · three-tier model · overlays ·<br/>swing / range · workflow · snapshots.<br/>FX carried NOT converted (GBP + local currency fields)."]:::pig
  end
  WB["Write-back to a<br/>Snowflake table"]:::sys
  DOWN["Downstream reporting<br/>(Power BI approx 3-hourly)"]:::sys
  WD --> DIMS
  SF -->|"approx hourly refresh"| MASTER
  MASTER -->|"direct read · delta loads (changed records only) · minimal footprint"| PIG
  DIMS -.->|"mapping / hierarchies"| PIG
  PIG --> WB
  WB --> DOWN
  PRIN["KEY PRINCIPLE: logic lives in Pigment, NOT baked into the Snowflake curated layer.<br/>Delta loads (changed records only) · minimal read footprint ·<br/>annual FX rate rebased yearly · FX carried not converted.<br/>Full physical source-to-target = a later data-architecture session (out of scope here)."]:::note
  PGG -.- PRIN
  SFG -.- FRAME

Open items to preserve

Flagged on the diagrams above, not silently resolved.

  • Renewal layer position — placed above New Deals, below Target (Viridian default; overrideable).
  • Deal-backed pooling of material-uncommittable deals — needs James/Ken sign-off; mutually-exclusive membership, rule-defined, consumes upside range.
